# Arete quality audit, 13 Oct 2026

Scope: the whole repository (React 19, Vite 7, Tailwind 3, Supabase, Tauri 2, PWA on Netlify). Method: read the code, trace the important paths, run the tests and builds, and exercise the changed screens in a browser against an in-memory Supabase stand-in. **Nothing here was tested on a real iPhone, on Android, against the real Supabase project, or with Lighthouse.** Each item says which kind of evidence backs it.

Evidence words: **Confirmed** = seen in code or reproduced. **Fixed** = changed and verified (tests, build, or browser). **Unverified** = suspected or needs a real device. **Optional** = nice to have.

## A. Audit report

### What is already good (confirmed)
- 736 unit tests pass; desktop (Tauri) and PWA builds pass; `npm audit` is clean for production dependencies after this session.
- Real-time sync for rows, and now for documents and settings. Supabase row-level security is owner-only on every table (SQL in `supabase/`).
- A root error boundary and a per-screen error boundary; a Sentry hook that is ready but has no DSN set.
- Safe-area insets (`viewport-fit=cover`, `env(safe-area-inset-*)`), reduced-motion support, 277 `aria-label` uses.
- Backup export and restore exist (command palette, Data section).
- The anon key bundled in the client is a Supabase `anon` role key, as designed (checked by decoding it); no service or AI keys are in the bundle.

## B. Feature gap checklist
**Implemented and verified:** offline-safe row and document saving; live sync of rows, documents and settings; update prompt; launch screen; six-tab navigation; customisable Home; 16 split types, per-day sets and reps, swap, muscle-coverage check; exercise demos; sync check screen; production dependencies clean.
**Partly implemented:** Face ID (works only if iOS allows the passkey in the installed app); push notifications (code exists, backend not deployed); offline *reading* (screens read from local mirrors, but photos and the food search's online lookups need a connection); accessibility.
**Missing:** URL routing and deep links; crash reporting enabled; UI/e2e tests; route-level code splitting; install screenshots; app shortcuts.
**Needs a real device:** Face ID, haptics, install flow, safe areas on a notched phone, offline start, Health Auto Export.
**Not relevant:** multi-user accounts, payments, an app store release, localisation beyond English/Australian.

## C. Roadmap (in order)
1. **Done in this pass:** P0 items 1-3, P1 items 4-10, P2 item 11.
2. **URL routing** (hash or history) so Back works and a screen can be linked. Medium; low risk if done as a thin layer over the existing `activeTab` state.
3. **Smoke and journey tests** with Playwright (log a set offline, reconnect, see it synced). Medium; adds one dev dependency; best run against a staging Supabase project.
4. **Lazy-load screens** (`React.lazy` per tab) and re-measure; target a smaller first load. Medium.
5. **Turn on Sentry** with the DSN; scrub health fields. Small.
6. **Accessibility pass** with axe and a screen reader on the new Home, Train and Look screens. Medium.
7. **Delete the dead screens** after a final data export. Small.
